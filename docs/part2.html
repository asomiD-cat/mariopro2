1. finder.hh — Spatial Grid

A generic template class that maps objects to grid cells. Only objects in cells that overlap the query rect are returned.

private:    const int cellSize = 40;    std::map<std::pair<int, int>, std::set<const T*>> grid;     void gridRange(const pro2::Rect& element_rect, pro2::Rect& tiles) const {        tiles.bottom = floor(element_rect.bottom / cellSize);        tiles.top    = floor(element_rect.top    / cellSize);        tiles.left   = floor(element_rect.left   / cellSize);        tiles.right  = floor(element_rect.right  / cellSize);    }

Note: query runs in O(k log n) where k is the number of cells in the query window. For a fixed-size camera viewport, k is constant, making it effectively O(log n).

Optimization Check

We can manually verify the optimization by setting the loop limit to 500000:

C++game.cc — constructor 
for (int i = 1; i < 500000; i++) {    platforms_.push_back(Platform(250 + i * 200, 400 + i * 200, 150, 161));    coins_.push_back(Coin({250 + i * 200,      140}));    coins_.push_back(Coin({250 + i * 200 - 60, 140}));    coins_.push_back(Coin({250 + i * 200 + 60, 140}));}
Without the finder: every frame iterates all 1.5M coins — the game becomes unplayable.
With the finder: only the ~20 objects near Mario are queried per frame, regardless of total count. The game runs smoothly at 500k platforms and 1.5M coins.
