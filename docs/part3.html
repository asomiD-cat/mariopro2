💥 Crumbling Platforms Feature

Adding a new platform type that shakes and falls when Mario stands on it, then respawns after a cooldown.

General strategy: Crumbling is modelled after Platform — same private fields (left_, right_, top_, bottom_), same constructor signature, same get_rect() and paint(). Copy platform.hh as a starting skeleton and add the state machine on top.

1. crumbling.hh — New Class

The Crumbling class models a platform with four states: "normal" → "shaking" → "falling" → "fallen", cycling back to "normal" after a cooldown.

State string & constants

C++crumbling.hh — private 
class Crumbling { public:  private:    int left_, right_, top_, bottom_;   // same as Platform    std::string state_;                 // string-based state representation    int   timer_;     static const std::vector<std::vector<int>> crumbling_texture_;     static const int SHAKE_FRAMES   = 60;  // 1.25 sec at 48 fps    static const int FALL_FRAMES    = 30;  // 0.6 sec    static const int FALLEN_FRAMES  = 96;  // 2 sec cooldown
Frame counts = seconds × FPS. FPS is 48 (see main.cc). So 1.25 sec = 60 frames, 2 sec = 96 frames.

Constructor

Identical signature to Platform — copy it directly:

C++crumbling.hh — constructor 
    Crumbling(int left, int right, int top, int bottom)        : left_(left), right_(right), top_(top), bottom_(bottom),          state_("normal"), timer_(0) {}

update() — state machine

Called every frame. Each active state increments timer_ and transitions when its threshold is reached. "normal" has no timer — it waits for mario_on_top():

C++crumbling.hh — update 
    void update() {        if (state_ == "shaking") {            timer_++;            if (timer_ >= SHAKE_FRAMES) {                state_ = "falling";                timer_ = 0;            }        } else if (state_ == "falling") {            timer_++;            if (timer_ >= FALL_FRAMES) {                state_ = "fallen";                timer_ = 0;            }        } else if (state_ == "fallen") {            timer_++;            if (timer_ >= FALLEN_FRAMES) {                state_ = "normal";                timer_ = 0;            }        }    }

Key public methods

C++crumbling.hh — public 
    // Called by game.cc when mario is standing on it    void mario_on_top() {        if (state_ == "normal") {            state_ = "shaking";            timer_ = 0;        }    }     bool is_solid() const {        return state_ == "normal" || state_ == "shaking";    }     std::string state() const { return state_; }    int top() { return top_; }     // Returns empty rect when fallen — Finder and overlaps skip it automatically    pro2::Rect get_rect() const {        if (state_ == "fallen") return {0, 0, 0, 0};        return {left_, top_, right_, bottom_};    }     bool has_crossed_floor_downwards(pro2::Pt plast, pro2::Pt pcurr) const {        if (!is_solid()) return false;        return (left_ <= plast.x && plast.x <= right_) &&               (left_ <= pcurr.x && pcurr.x <= right_) &&               (plast.y <= top_   && pcurr.y >= top_);    }     void paint(pro2::Window& window) const;}; #endif
get_rect() trick: returning {0,0,0,0} when fallen means overlaps() with any real rect returns false and Finder::query() won't find it either — zero extra logic needed in game.cc.

2. crumbling.cc — Final File

The texture tiling loop in paint follows the exact same pattern as platform.cc — copy it as a starting point. The only additions are the offset_x wobble (shaking) and offset_y drop (falling).

C++crumbling.cc 
#include "crumbling.hh"#include <vector>using namespace std; const int _ = 0;           // transparentconst int r = pro2::red;const int y = pro2::yellow;const int w = pro2::white; const vector<vector<int>> Crumbling::crumbling_texture_ = {    {w, w, w, w, w, w, _},    {w, y, y, w, y, y, _},    {y, y, r, y, y, r, _},    {_, _, _, _, _, _, _},    {w, w, _, w, w, w, _},    {y, y, y, _, y, y, y},    {y, r, y, y, _, r, y},    {_, _, _, _, _, _, _},}; void Crumbling::paint(pro2::Window& window) const {    if (state_ == "fallen") return;     const int txH = static_cast<int>(crumbling_texture_.size());    const int txW = static_cast<int>(crumbling_texture_[0].size());     // shaking: alternate ±1px left/right every 2 frames    int offset_x = 0;    if (state_ == "shaking") {        offset_x = (timer_ % 4 < 2) ? 1 : -1;    }     // falling: drop 4px per frame    int offset_y = 0;    if (state_ == "falling") {        offset_y = timer_ * 4;    }     for (int i = top_ + 1; i <= bottom_; i++) {        for (int j = left_; j <= right_; j++) {            int color = crumbling_texture_[(i - top_ - 1) % txH][(j - left_) % txW];            if (color != 0) {                window.set_pixel({j + offset_x, i + offset_y}, color);            }        }    }}

3. game.hh — Changes

Three additions following the existing Platform / Finder<Platform> pattern:

C++game.hh 
#include "crumbling.hh" class Game {    Mario                  mario_;    std::vector<Platform>  platforms_;    std::vector<Crumbling> crumbling_platforms_;    int                    score_;    std::vector<Coin>      coins_;    Finder<Platform>       platform_finder_;    Finder<Coin>           coin_finder_;    Finder<Crumbling>      crumbling_finder_;    ...};
Pattern: every new object type gets a std::vector<T> to own the objects and a Finder<T> for spatial queries. The vector must outlive the finder since the finder stores raw pointers into it.

4. game.cc — Changes

Constructor

The loop now branches: every 3rd platform (i % 3 == 0) becomes a Crumbling. After the loop, all three finders are registered.

C++game.cc — constructor 
#include "crumbling.hh"  // new include     for (int i = 1; i < 20; i++) {        if (i % 3 == 0) {            crumbling_platforms_.push_back(Crumbling(250 + i*200, 400 + i*200, 150, 161));        } else {            platforms_.push_back(Platform(250 + i*200, 400 + i*200, 150, 161));        }        coins_.push_back(Coin({250 + i * 200,       140}));        coins_.push_back(Coin({250 + i * 200 - 60,  140}));        coins_.push_back(Coin({250 + i * 200 + 60,  140}));    }    for (const auto& p  : platforms_)           platform_finder_.add(&p);    for (const auto& cp : crumbling_platforms_) crumbling_finder_.add(&cp);    for (const auto& c  : coins_)              coin_finder_.add(&c);
Always register finders AFTER the loop. Calling push_back can reallocate the vector, invalidating all pointers. If you add &p inside the loop and the vector reallocates, you get dangling pointers.

update_objects — two new blocks

Block 1 (before mario_.update): feed solid crumbling platforms into nearby as temporary Platform objects — Mario's physics doesn't know about Crumbling. Block 2 (after mario_.update): tick each crumbling platform and trigger shaking if Mario is standing on it.

C++game.cc — update_objects 
void Game::update_objects(pro2::Window& window) {    std::vector<Platform> nearby;    Rect aux = mario_.get_rect();    aux.left -= 480; aux.right += 480;    aux.top  -= 480; aux.bottom += 480;     for (const Platform* p : platform_finder_.query(aux))        nearby.push_back(*p);     for (Crumbling& cp : crumbling_platforms_) {        if (cp.is_solid())            nearby.push_back(Platform(cp.get_rect().left, cp.get_rect().right,                                      cp.top(), cp.top() + 11));    }     mario_.update(window, nearby);     Rect mariorect = mario_.get_rect();    for (Crumbling& cp : crumbling_platforms_) {        if (mario_.is_grounded() && overlaps(mariorect, cp.get_rect()))            cp.mario_on_top();        cp.update();    }     Rect visible = window.camera_rect();    for (Coin& c : coins_) {        if (!c.is_collected() && overlaps(c.get_rect(), visible)) {            c.update(window.frame_count());            if (overlaps(c.get_rect(), mariorect)) {                c.collect();                coin_finder_.remove(&c);                std::cout << "You have " << score_++ << " coins.\n";            }        }    }}
Order matters: call mario_.update() first (so is_grounded() is fresh for this frame), then check mario_.is_grounded() + overlaps to trigger mario_on_top(), then call cp.update() to advance the state machine.
Why cast to Platform? mario_.update() takes vector<Platform>. Wrapping the crumbling rect as a temporary Platform reuses existing physics without changing Mario or Platform.

paint — one new line

void Game::paint(pro2::Window& window) {    window.clear(sky_blue);    Rect visible = window.camera_rect();    for (const Platform* p  : platform_finder_.query(visible))        p->paint(window);    for (const Crumbling* cp : crumbling_finder_.query(visible))        cp->paint(window);    for (const Coin* c  : coin_finder_.query(visible))        c->paint_coin(window);    mario_.paint(window);}
